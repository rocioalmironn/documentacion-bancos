01 Visión General

La tool bancos gestiona el universo de cuentas bancarias del grupo Trasa: visualización de saldos (automáticos vía DW y manuales), histórico, maestro de cuentas, catálogo de bancos y carga manual de saldos.

03 Sistema de Permisos

Tres niveles de acceso

Nivel 1 — Session
@requiere_session
Cualquier usuario autenticado con acceso a la tool. Puede ver Dashboard, Saldos, Histórico, Maestro de Cuentas (solo lectura), marcar/desmarcar favoritas.
Nivel 2 — Permiso granular
carga-manual-saldos
Usuario con fila activa en bancos_user_permisos, O cualquier admin (bypass). Puede cargar saldos (unitario y masivo), descargar plantilla, ver historial de cargas.
Nivel 3 — Admin
@requiere_bancos_admin
Company admin o access_level='admin' en user_tool_access. TODO lo anterior + Configuración, ABM maestro/catálogo, habilitar/deshabilitar cuentas, gestionar permisos, eliminar cargas.

Tabla SQL — bancos_user_permisos

019_bancos_user_permisos.sql
CREATE TABLE IF NOT EXISTS bancos_user_permisos (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  user_id     BIGINT UNSIGNED NOT NULL,
  company_id  BIGINT UNSIGNED NOT NULL,
  permiso_key ENUM('carga-manual-saldos') NOT NULL,
  is_active   TINYINT(1)      DEFAULT 1,
  assigned_by BIGINT UNSIGNED NOT NULL,
  created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uq_bancos_user_permiso (user_id, company_id, permiso_key)
);

07 Ejemplos de Uso

Carga unitaria — paso a paso

  1. Entrar a Bancos → Carga manual (requiere permiso carga-manual-saldos).
  2. En la pestaña Cuentas se listan todas las cuentas no automatizadas.
  3. Hacer clic en el botón ⊕ de la cuenta a cargar.
  4. Completar Fecha del saldo (no puede ser futura), Saldo (puede ser negativo para cuentas en descubierto) y opcionalmente Observaciones (máx 255 caracteres).
  5. Si ya existía un saldo vigente, se muestra un aviso: "Esta carga lo va a reemplazar como vigente."
  6. Clic Confirmar → toast de éxito. La nueva carga pasa a ser la vigente.

Importación masiva — paso a paso

  1. En la pestaña Cuentas, clic en Importar Excel.
  2. Descargar la plantilla (ya viene con una fila por cuenta cargable).
  3. Completar solo Fecha del saldo y Saldo en las filas que se necesitan. El resto puede quedar vacío.
  4. Subir el archivo → clic Validar archivo (dry-run, no escribe nada).
  5. Revisar el resumen: total, válidas, errores, advertencias.
  6. Si hay errores → corregir el archivo y volver a subir.
  7. Si no hay errores → clic Continuar y guardar (inserta todo en una transacción atómica).
  8. Toast de éxito con cantidad de cargas insertadas.

08 API Reference

Carga Manual de Saldos

GET /api/bancos/saldos-manuales/cuentas

Permiso: carga-manual-saldos

Lista el universo de cuentas no automatizadas con su saldo vigente anidado.

POST /api/bancos/saldos-manuales

Permiso: carga-manual-saldos  |  Modelo: append-only

Campo Tipo Req Validación
maestroId int ✓ Debe existir en bancos_maestro
fechaSaldo string ✓ Formato YYYY-MM-DD, no futura
saldo number|string ✓ Decimal válido, puede ser negativo
observaciones string|null ✗ Máx 255 chars, se trimea
Status Significado
201 Carga creada. Body: { ok, data: { id, saldo, fechaSaldo } }
400 maestroId / fechaSaldo / saldo inválidos
403 Sin permiso carga-manual-saldos
404 No existe cuenta con ese maestroId
409 Cuenta automatizada o deshabilitada
GET /api/bancos/saldos-manuales/plantilla

Permiso: carga-manual-saldos  |  Response: archivo .xlsx como attachment

Una fila por cada cuenta cargable: ID Interno, Empresa, Banco, Cuenta, Moneda, Fecha del saldo, Saldo.

POST /api/bancos/saldos-manuales/importar/validar

Permiso: carga-manual-saldos  |  Content-Type: multipart/form-data

NUNCA escribe. Dry-run puro. Devuelve resumen con errores y advertencias.

POST /api/bancos/saldos-manuales/importar

Permiso: carga-manual-saldos  |  Re-valida todo desde cero.

Si 0 errores → transacción única (todo o nada) con import_batch_id compartido. Si hay errores → 422, nada se escribe.

GET /api/bancos/saldos-manuales/historial

Permiso: carga-manual-saldos

Param Tipo Default Descripción
desde string — Formato YYYY-MM-DD
hasta string — Formato YYYY-MM-DD
maestroId int — Filtro opcional por cuenta
page int 1 Página actual
pageSize int 50 Items por página (máx 200)
DELETE /api/bancos/saldos-manuales/<id>

Permiso: requiere_bancos_admin (no basta con carga-manual-saldos)

Baja lógica: marca deleted_at/deleted_by, no borra la fila. Única forma de corregir una carga con fecha mal tipeada (modelo append-only).

09 Edge Cases Cubiertos

Permisos y Acceso 10
# Edge Case Comportamiento
1 user_id es None Fail-closed: (set(), False)
2 company_id no resoluble Fail-closed: (set(), False)
3 permiso_key fuera de BANCOS_PERMISOS (typo) Deniega siempre, nunca permite
4 Clave retirada del código pero presente en DB Filtrada contra whitelist en Python
5 Admin intenta modificar su propio permiso 409: "No podés modificar tu propio permiso"
6 target_user_id inválido (no int) 400: "target_user_id inválido"
7 Revocar permiso ya no activo Idempotente: no falla
8 Asignar permiso ya activo Upsert: ON DUPLICATE KEY UPDATE is_active=1
9 URL /carga-manual navegada a mano sin permiso Skeleton → bloque destructive
10 Sidebar: flash del item antes de resolver permiso Se oculta durante permisosLoading
Carga Unitaria 10
# Edge Case Comportamiento
11 maestroId no existe 404
12 Cuenta automatizada (tiene fila en DW) 409: no cargable
13 Cuenta deshabilitada 409: no cargable

15 fechaSaldo formato incorrecto 400

10 Decisiones de Diseño

Tabla append-only (sin UPDATE)
Cada carga es un registro contable con autoría. Editar borraría la traza. Corregir = cargar de nuevo.
Saldo vigente derivado
No se almacena. Se calcula: MAX(fecha_saldo, created_at, id). Evita inconsistencias entre tablas.
Moneda como snapshot
Si el ABM corrige la moneda, el historial conserva en qué moneda se cargó cada importe.
FK por maestro_id, no accounts_id
Cubre cuentas pendientes (sin ID de DW). 100% del universo cargable tiene maestro_id.
Importación re-valida todo
Elimina race conditions entre /validar y /importar. Otro usuario pudo cambiar datos entre medio.
Permiso granular, no ladder de roles
Bancos tiene UNA capacidad puntual (carga-manual-saldos). Inventar admin/editor/lector sería artificial.
Admin bypass sin fila en permisos
Un admin puede todo automáticamente. No necesita asignación explícita del permiso.
Fail-closed en cada salida
Sin user_id, sin company_id, o con permiso_key inválida → deniega siempre, nunca permite.
Soft delete para eliminación
Trazabilidad completa: quién cargó y quién eliminó siempre queda registrado en el historial.
